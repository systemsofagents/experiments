# Track 03: Search and hill climbing

**Status:** Proposed experiments; no results yet.

This track studies two ways to improve a system of agents. It can search for a better trajectory within one task, or learn across tasks which changes to its own configuration lead to better outcomes. It complements [Track 01: The uncapped session](01-uncapped-session.md). Within a task, does judge-guided search return a better verified result for the same spend? Across tasks, does changing the agent system improve the next session, including its difficult cases? A session can answer the first question. The second requires repeated, independent runs of the system-improvement process and evaluation on tasks held out from that process.

## Separate proposing, judging, and verifying

A proposer supplies a policy over possible next actions. If token log probabilities are available, they can help rank a constrained set of actions, but they measure the model's likelihood of an encoding, not the resulting trajectory's chance of success. Sampling or asking for structured candidates works without logits. A judge estimates the value of a partial path under a continuation policy and remaining budget. It can rank paths and decide where to spend more effort. A verifier measures the final outcome independently. [Tree of Thoughts](https://arxiv.org/abs/2305.10601) is a precedent for model-proposed branches and model-guided evaluation, not evidence that this search helps durable sessions.

## Experiment 03A: Does guided search improve delivery at equal spend?

Reuse Track 01B's synthetic, correction-sensitive archive fixture in a resettable simulated environment. An old instruction and a later correction disagree about an appointment. After both fall out of working context, the agent must make the currently authorized edit, preserve unrelated entries, and cite the governing source. Include a missing-evidence control where asking instead of acting is correct. A frozen checker grades final state, cited evidence, and the event log. Speculative branches use isolated snapshots with no real side effects; only the selected trajectory may commit in the fixture. Terminal-state checking and repeated-trial reliability have a precedent in [τ-bench](https://arxiv.org/abs/2406.12045).

1. **Compare two inner-loop policies.** Give both the same proposer, tools, initial state, and task instances. The guided policy explores continuations and uses a judge to choose which to pursue and return. The baseline spends the same allowance on independent direct attempts and selects from the completed attempts using the same terminal judge. Also retain the direct single-trajectory policy as a reference. With the proposer and terminal judge held fixed, the matched comparison tests whether adaptive branching helps more than spending on more independent attempts. Charge proposal, judge, and tool calls to each policy. Keep the independent checker hidden from both.
2. **Measure progress at common spend checkpoints.** Let each session stop naturally within a declared budget cap. At each checkpoint, record the result the policy could actually return using only information available by then. Carry a finished session’s answer forward and retain its actual cost. Verify these snapshots offline. A correct discarded branch counts as evidence about the proposer, while only the returned result counts as a delivery success. Search strategy and allocation of test-time compute can affect outcomes even with the same underlying model. [Snell et al.](https://arxiv.org/abs/2408.03314)
## Experiment 03B: Can a system improve steadily across tasks?

**Compare two outer-loop policies.** Start both from the same agent configuration. Let hill climbing propose changes to one component, such as the stopping rule, and accept candidates on a development panel. Reflective prompt search has a precedent in [GEPA](https://arxiv.org/abs/2507.19457); start with a smaller controlled experiment. Give random configuration search the same configuration space, starting point, development tasks, and total evaluation spend. Freeze each policy’s incumbent at predeclared spend checkpoints. Evaluate the frozen configurations on a locked task panel at the same per-session allowance. Repeat the entire outer search with fresh seeds. Release held-out results only after the trajectories are frozen. Repeatedly using the same panel to make design choices turns it into development data; use a fresh confirmation panel if that happens. [Dwork et al.](https://arxiv.org/abs/1506.02629)

## Starter scorecard

| Measure | What to report | What it can miss |
|---|---|---|
| **Verified success at fixed spend** | At each checkpoint, report the task-weighted fraction of returned results that pass and the paired difference from baseline. For the outer loop, plot held-out success against cumulative development spend. | A single checkpoint hides crossing curves. An average can hide regressions on difficult tasks. |
| **Spend to a fixed target** | For sessions, plot the fraction whose returnable result has passed at least once by each spend level. For outer runs, use the first frozen incumbent that reaches a predeclared held-out quality target. Keep all runs in the denominator and mark administrative censoring. | Averaging only successful runs favors unreliable methods. First hits also hide later regressions and do not imply the agent knew when to stop. |
| **Repeatability and tail failure** | Report the fraction of tasks passing all of a fixed number of independent repeats, alongside the count and denominator of severe failures such as unintended edits. | All-repeat success depends on the repeat count. Zero observed severe failures can still be consistent with material risk. |
| **Paired perturbation loss** | Replay the same task and initial state with a meaning-preserving paraphrase or one recoverable tool timeout. Report clean and perturbed success, clean-pass-to-perturbed-fail counts, and results by perturbation. | A net difference can conceal failures offset by improvements. The result covers only the tested perturbations. |
| **Judge calibration and selection** | If the judge predicts a probability of success, compare predicted with observed pass rates in score bins and report Brier score. Audit a random sample of candidates and the selected returns separately, stratified by search budget. On fully audited sessions, count cases where a passing candidate existed but the judge selected a failure. | Calibration across all candidates can hide poor ranking among finalists. A growing selected-score advantage can reflect optimization of judge error. Sparse audits can miss passing alternatives. |

Use the same declared primary spend unit for comparisons (for example dollars), and log model calls, tokens, judge calls, tool calls, and elapsed time separately. Count all proposal and selection work; parallelism can reduce time without reducing spend. Report runtime percentiles and counts at a deadline. The fixed-budget and fixed-target views adapt COCO’s benchmarking framework. The repeated-trial measure follows τ-bench. The separate audit of winners addresses a failure demonstrated under proxy-reward optimization, where additional optimization can improve proxy scores while degrading an independent measure. [Hansen et al.](https://arxiv.org/abs/1605.03560) · [Yao et al.](https://arxiv.org/abs/2406.12045) · [Gao et al.](https://arxiv.org/abs/2210.10760)

## Stability, fragility, and robustness

Use **repeatability** for variation across reruns under the same setup, **robustness** for change under a specified perturbation, and **tail risk** for the frequency and severity of bad outcomes. A consistently wrong agent can be repeatable. A robust agent can take different paths and still reach the right state. Label a large drop under a small tested perturbation **fragility** rather than rolling it into a generic stability score. Treat forbidden side effects as a separate promotion gate, not a penalty that a higher average can buy off.

## Progress, plateaus, and trade-offs

**Define a plateau before inspecting the curve.** Pick a spend interval and the smallest improvement worth paying for. Estimate the paired change over that interval, with uncertainty across tasks and seeds. If the whole interval estimate falls inside the predeclared band of negligible change, the data support a practical plateau over that spend range. If it includes both negligible and worthwhile gains, the result is inconclusive. Preserve paired tasks, repeat structure, and entire outer-run trajectories when resampling. If the panel is fixed, distinguish uncertainty across seeds from generalization to new tasks. Branches from one session are correlated. [Agarwal et al.](https://arxiv.org/abs/2108.13264)

**Many adjustable choices can still serve one objective.** Prompts, routing rules, tool order, and stopping thresholds can form a high-dimensional *decision space* while the experiment optimizes one quantity, such as verified success under a fixed allowance. Introduce multiple objectives when a real choice remains among outcomes, such as success, latency, and severe-failure rate.

- **Pareto dominance** identifies a configuration that is at least as good on every objective and strictly better on one. It leaves genuine trade-offs unresolved. Show uncertainty before treating small point-estimate differences as dominance.
- **Hypervolume** summarizes how much objective space a set of configurations dominates relative to a fixed reference point. Use it to compare whole sets at equal outer-loop spend, with identical units and a predeclared reference point. Its ranking can depend on that point, and its scalar value hides where a gain occurred. [Ishibuchi et al.](https://pubmed.ncbi.nlm.nih.gov/29786458/)
- **Empirical attainment** answers an operational question across independent outer runs. For example, what fraction produced at least one configuration meeting both a verified-success threshold and a latency limit? A two-objective attainment plot shows where a method reliably delivers a trade-off. With few outer runs, those fractions are coarse. [López-Ibáñez, Paquete, and Stützle](https://doi.org/10.1007/978-3-642-02538-9_9)

For the first evaluation, the decision is whether guided search improves **verified returned success at equal spend**, with repeatability, severe failures, and perturbation loss visible beside it. The outer-loop comparison then tests whether hill climbing can improve that same held-out result more efficiently than random configuration search. No experiments have been run.
